# HorseRPG 简要使用指南

本指南同时面向 PLAYER 与 GM，说明当前版本的主要页面、常用流程和高风险操作。

> 使用原则：PLAYER 提交意向，GM 根据跑团实际情况作出最终裁定。页面上的状态以服务器保存结果为准。

## 1. 登录与角色

### PLAYER

PLAYER 账号必须绑定一个 Owner。登录后可以：

- 查看 Owner、Horse、比赛和交易资料；
- 为自己 Owner 名下的 Horse 提交比赛报名意向；
- 参与庭先询问、秘密报价和公开拍卖；
- 为符合条件的现役 Horse 提交退役申请；
- 查看 GM 已确认的赛程、赛果和处理结果。

PLAYER 不能进入 GM 管理页面，也不能直接修改比赛事实、交易结果、资金流水或 Winning Post 时间。

### GM

GM 登录后可以在两种工作区之间切换：

- **GM 工作台**：处理审核、排程、赛果、交易、时间和基础资料；
- **玩家视图**：查看玩家所见页面，便于检查公开信息。

玩家视图不会把 GM 伪装成某个 PLAYER，也不会赋予 GM 某位 Owner 的报价资格。

## 2. 通用界面

- 左侧菜单用于切换业务模块；手机端通过顶部菜单按钮打开抽屉导航。
- 顶栏显示当前 Winning Post 时间、身份和账号。
- GM 可以点击顶栏的 **管理时间** 进入时间推进页，但不能直接在顶栏推进时间。
- 页面中的黄色或红色区域通常表示待确认、高风险或异常操作。
- 提交按钮显示“正在处理”时不要重复点击；完成后以页面提示和刷新后的状态为准。
- 若实时连接中断，公开拍卖会暂停报价操作，等待状态恢复后再继续。

## 3. PLAYER 使用流程

### 3.1 查看 Owner 与 Horse

通过 **马主名录** 和 **马匹档案** 可以查看公开资料。

Horse 详情通常包含：

- 名称、编号、性别、毛色和生命周期；
- 父系、母父系和 Horse Factors；
- 已确认战绩、赛程、伤病和健康记录；
- 当前 Owner、奖金及可用操作。

如页面显示“等待 GM 处理”，代表意向已经提交，PLAYER 不需要重复提交。

### 3.2 提交比赛报名意向

进入 **比赛与报名**：

1. 选择自己名下符合条件的 Horse；
2. 填写希望参加的 WP 年、月、周；
3. 选择固定比赛，或填写未胜利赛、条件赛等比赛名称；
4. 可选填写骑手、跑法和 PLAYER 备注；
5. 点击 **提交报名意向**。

报名状态：

- `PENDING`：等待 GM 审核，可以撤回；
- `CONFIRMED`：GM 已确认，最终赛程可能与原意向不同；
- `REJECTED`：GM 已拒绝；
- `WITHDRAWN`：PLAYER 已撤回。

注意：提交的是报名意向，不是最终赛程。应以 **我的已确认赛程** 中的记录为准。

### 3.3 庭先交易

进入 **庭先交易** 并选择开放中的届次。

每届庭先交易中：

- 可以查看 Lot 中的幼驹、血统、Factors 和最低报价；
- 每个 Owner 在一届中只有一次 GM 询问机会；
- 秘密报价不会向其他 PLAYER 公开；
- 截止前可以修改或撤回报价；
- 报价会占用冻结资金，撤回后对应冻结会释放；
- 最终成交与否由 GM 结算，数据库会重新检查截止时间和可用资金。

不要把页面倒计时当作最终裁判；服务器时间和最终保存结果优先。

### 3.4 公开拍卖

进入 **公开拍卖**，选择当前 Event 后进入现场页面。

拍卖过程：

1. 等待 GM 展示当前 Lot；
2. 查看 Horse 资料、五份评价、起拍价和评价价值；
3. GM 开始竞价后，输入报价或使用快捷加价；
4. 再次核对当前价格、最高出价者、可用资金和倒计时；
5. 点击 **提交报价**；
6. 以“报价已被服务器接受”的反馈为准。

报价要求：

- 只有绑定 Owner 的 PLAYER 可以报价；
- 当前最高出价者不能对自己继续加价；
- 报价必须符合起拍价、最小加价和金额步进规则；
- 可用资金不足时服务器会拒绝报价；
- 本地倒计时仅供参考，服务器会判断竞价是否已经结束。

GM 确认后，页面会显示成交 Owner、成交价或流拍结果。

### 3.5 退役申请与奖金

符合条件的现役 Horse 可以在 Horse 详情页提交退役申请。

- 主动申请通常从 3 岁开始开放；
- 提交后 Horse 进入退役处理中，并停止创建新的已确认赛程；
- PLAYER 可以撤回尚未处理的主动申请；
- 退役不会在提交申请时立即生效；
- GM 最终确认后，Horse 才会正式退役并释放待结算奖金。

通过 **退役与奖金** 可以查看待释放奖金和申请历史。

## 4. GM 工作台

进入 **GM 工作台** 后，菜单分为：

- **工作台**：管理总览、时间推进；
- **赛事**：报名与赛程、赛果录入、退役结算；
- **市场与繁育**：庭先交易、公开拍卖、繁育管理；
- **基础资料**：马匹、马主、用户。

管理总览第一屏显示当前时间、下一周预览和实时待办：

- 待审核报名；
- 待录赛果；
- 待处理退役；
- 未回答庭先询问；
- 待结算庭先届次；
- 已关闭待确认的拍卖 Lot。

数字为 0 时入口仍然保留，方便 GM 检查空状态。

## 5. GM 常用流程

### 5.1 Winning Post 时间推进

进入 **时间推进** 后，先查看：

- 当前时间与下一时间；
- 本周已确认但尚未录入有效赛果的赛程；
- 推进后会早于新时间的待审核报名；
- 本周结束、下一周可能恢复参赛的伤病。

这些预检只提供提醒，不会阻止推进，也不会自动修改业务记录。

正常推进步骤：

1. 检查当前时间和下一周；
2. 查看影响预检；
3. 如有需要，先到对应业务页处理；
4. 点击 **推进到下一周**；
5. 阅读二次确认内容并确认执行。

每次正常操作只推进一周：

- Week 1 → 2 → 3 → 4 → 5；
- Week 5 后进入下个月 Week 1；
- 12 月 Week 5 后进入下一年 1 月 Week 1。

时间推进不会自动改变赛程、报名、伤病、奖金、退役或交易状态。

#### 高级时间纠正

只有发生录入错误时才使用 **高级时间纠正**：

1. 填写正确的年、月、周；
2. 填写非空纠正原因；
3. 输入严格确认文本 `CORRECT WP TIME`；
4. 完成第二次确认。

纠正可以向前或向后调整，前后时间、操作人、原因和现实操作时间都会写入审计记录。

### 5.2 报名审核与排程

进入 **报名与赛程**：

1. 优先处理 **待审核报名**；
2. 左侧核对 PLAYER 原始意向，该部分只读；
3. 在 GM 最终确认区域调整实际时间、比赛、骑手和跑法；
4. 确认赛程，或填写原因拒绝申请；
5. 必要时使用 **GM 直接安排赛程** 创建权威赛程。

确认时系统会重新检查 Horse 状态、Owner、伤病、时间和同周冲突。

比赛目录是报名选项资料。停用目录不会删除历史报名或已确认赛程。

### 5.3 赛果录入

赛果由三个独立事实组成：

- PLAYER 报名意向；
- GM 已确认赛程；
- Actual Race 与最终赛果。

操作顺序：

1. 创建 Actual Race；
2. 进入比赛详情；
3. 明确关联参加该场实际比赛的 Confirmed Entries；
4. 录入名次、奖金、实际骑手和跑法；
5. 核对后提交有效赛果；
6. 如需纠错，使用详情中的修正或作废流程，不要创建重复记录代替纠错。

计划赛程与实际比赛允许不同，但必须由 GM 明确记录。

### 5.4 庭先管理

庭先届次通常按以下顺序处理：

1. 创建草稿届次并设置开始、截止时间；
2. 将符合条件的幼驹加入 Lot；
3. 开放届次；
4. 回答 PLAYER 询问；
5. 截止后关闭届次并进入审核；
6. 核对有效秘密报价和系统推荐结果；
7. 按系统结果成交或确认未成交；
8. 所有 Lot 完成后确认届次状态。

GM 例外裁定只用于明确需要偏离系统推荐结果的情况，必须选择另一条有效报价并填写原因。

草稿届次或 Lot 的移除属于危险操作，仅能在尚未开始且没有业务历史时执行。

### 5.5 公开拍卖主持

主持顺序：

1. 创建 Event 和 Lot；
2. 为当前 Lot 准备五份评价；
3. 开放 Event；
4. 展示当前 Horse；
5. 点击 **开始竞价**；
6. 观察公开报价和服务器倒计时；
7. 关闭当前 Lot；
8. 确认成交或流拍；
9. 继续下一 Lot；
10. 所有 Lot 完成后结束 Event。

普通重新开放需要填写原因。Emergency Rollback 只用于重大错误，会使用两阶段严格确认并保留原 Bid、结算和资金历史。

### 5.6 退役与奖金结算

处理退役申请前必须核对：

- Horse、Owner 和申请类型；
- 是否存在未来已确认赛程；
- 待释放奖金及每笔奖金对应的历史 Owner；
- G1 胜场或 WP 寿命等强制退役依据。

存在未来赛程时不能确认退役，应先按既有赛程流程处理。

最终确认会在同一数据库事务中：

- 将 Horse 设为已退役；
- 释放该 Horse 的所有待释放奖金；
- 写入账本与审计记录。

该操作不可通过普通页面撤销，确认前应再次核对全部资料。

### 5.7 基础资料

- **马匹**：维护 Horse 基础资料、生命周期、血统、Factors、体力和伤病；
- **马主**：维护 Owner 名称和基础资金资料；
- **用户**：创建 PLAYER、绑定 Owner、调整公开显示名称；
- **繁育管理**：维护繁育候选、血统事实和幼驹记录。

基础资料修改可能影响多个业务页面。修改 Owner 归属、Horse 生命周期或血统事实前，应先确认没有正在处理的比赛、交易或退役流程。

## 6. 推荐的每周 GM 操作顺序

1. 打开 GM 管理总览并检查全部待办；
2. 审核报名和未来赛程；
3. 创建并录入本周 Actual Races 与赛果；
4. 处理赛后状态、伤病和退役申请；
5. 完成到期的庭先或拍卖结算；
6. 进入时间推进页检查非阻断预检；
7. 确认没有遗漏后推进一周；
8. 返回管理总览确认待办数字是否符合预期。

## 7. 常见问题

### 为什么 PLAYER 提交后没有立刻出现在最终赛程？

PLAYER 提交的是意向，必须等待 GM 确认。最终事实以已确认赛程为准。

### 为什么按钮不可用？

常见原因包括：当前状态不允许操作、Horse 不符合条件、资金不足、实时连接中断、操作已经被其他人处理，或当前账号没有对应权限。

### 页面倒计时归零后为什么结果还没变化？

倒计时是显示辅助。公开拍卖需要服务器判断并由 GM 完成关闭或结算操作。

### 时间推进会自动恢复伤病或处理旧报名吗？

不会。预检只提示影响，所有业务记录仍由 GM 在相应工作台处理。

### 提交后页面提示时间或状态已经变化怎么办？

刷新页面，重新核对当前状态后再操作。这通常表示另一位 GM 或另一浏览器标签页已经先完成了处理。

### 发现严重录入错误怎么办？

停止继续推进相关流程，保留当前页面信息并联系 GM。GM 应优先使用现有纠错、作废或受控回滚功能，不要通过重复记录或直接修改数据库掩盖错误。

## 8. 安全提醒

- 不共享账号、密码或数据库密钥；
- 不在备注中填写密码、令牌或其他敏感信息；
- 高风险操作必须阅读二次确认内容；
- 不要同时在多个标签页重复提交同一操作；
- 发生异常时先刷新并核对状态，不要连续点击；
- 时间纠正、退役结算、交易例外裁定和拍卖回滚都应有明确原因。
